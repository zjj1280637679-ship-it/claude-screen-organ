# Claude Code 截图插件设计规范 v2

> 收敛说明:本规范把四路硬化产物(参数正交性 / 寻址DSL / 状态机边角 / 新能力威胁复审)与既有设计合并为单一可动工版本。四面在词汇与铁律上本就一致,真正的接缝有六处(模态默认方向、redact 双实现、ε_pool 计量单位、预检禁读语义 vs 期望谓词、回执信封字段合并、visibility 降级 vs 后台静默提权),已在下文逐一焊死。每节末尾标注归因。

---

## 1. 架构与立身目标

**单一 σ:** 为 AI 可靠地在任何情况下提供外界视觉/页面信息。
**可靠的兑现定义(降格后,可交付):** 可靠 ≠ 总能拿到正确信息;可靠 = AI 永远知道自己拿到的是什么、缺了什么、从哪来——**永不静默失败、永不返回半成品**。

**双后端,三类本机真实句柄。** 寻址 DSL 必须收敛到这三种句柄,解析失败一律 fail-closed 申报:
- `mcp_fullscreen` — computer-use screenshot/zoom。安全极(未授权应用像素打码),但**只有"主屏全屏"一种几何**,图直接回上下文(无法"截后先分析再决定入不入");zoom 仅子裁上一张全屏图。
- `chrome_tab` — 两套不兼容驱动:`control_chrome`(整数 tab_id + execute_javascript,默认只打活动标签)| `claude_in_chrome`(device_id + 自然语言 find 返回不透明 ref)。**CDP targetId 本机默认不存在**,仅当用户自起 `--remote-debugging-port` 才有 `cdp{endpoint,target_id}`。
- `os_window` — PowerShell:HWND + CopyFromScreen / PrintWindow(PW_RENDERFULLCONTENT) / WinRT OCR / UIAutomation / Graphics.Capture(WGC)。几何自由、可落盘、可先分析再入,但**绕过 allowlist 像素打码**——这是 v2 安全设计的核心张力,见第 6、10 节。

**backend=auto:** 默认走 `mcp_fullscreen`(安全极);几何超出主屏全屏、或需"截后先分析"、或需结构/后台路径,才落到代码后端,且强制在回执申报"已绕过像素打码"。

> 归因:双后端裂缝(安全 vs 自由)是 Claude Code 真实工具面貌强加的标准工程约束;把"可靠"降格为"永不静默+永不半成品"的可兑现承诺,是这套 AI 工具论的塑造——它拒绝给出做不到的"总能拿对"承诺。

## 2. 收紧后的参数模型:5 正交核心轴 + 模态私有子参数

诊断已定论:原 7 轴里 3 个是伪独立轴,根因单一——**modality 是隐藏主轴,visibility/redact/scale/stamp/sink.analyzed 都是它的函数**。修法统一:把派生轴沉到对应 modality 分支下,用判别联合(tagged union)让契约层根本无法表达跨模态非法组合(make illegal states unrepresentable)。

**5 个真正彼此独立、可自由组合的核心轴:**

```
target   : 寻址哪里      —— 判别联合,层级单调收窄(见第 3 节)
when     : 何时拍        —— now | after(ms) | on_appear(pred) | on_change
modality : 变成什么数据   —— structured | ocr | pixels(主轴)
validity : 质量门多严     —— none | basic | strict,判别集随 modality 分派
sink     : 加工+回什么    —— processing × return_shape
```

**其余全部降为 modality 私有子参数,只在对应分支可填:**
```
modality=pixels      → { capture_mode, scale, stamp, redact.pixel }
modality=ocr         → { confidence_threshold, redact.content }
modality=structured  → { redact.content, include_offscreen }
```

### 2.1 modality:主轴,且只负责"用什么形式把外界变成数据"

三档语义:`structured`(CDP DOM innerText / UIA 树 / markitdown,免疫遮挡、token 最低、**但泄露面最大**)→ `ocr`(WinRT 本地 OCR / Tesseract,中)→ `pixels`(CopyFromScreen / PrintWindow / WGC,受遮挡、token 高)。modality 不夹带后续加工(见 2.5 对 analyzed 的拆解)。

**默认选择(v2 翻转,焊死安全接缝):** 不再是"满足意图的最便宜层",而是 **"满足意图的最小泄露面层"**。文本目标若屏幕可见,优先本地 OCR 可见区,而非 DOM 全树;仅当可见区确不含目标(真在视口外)才升级 structured 并触发"深度读取"授权(见第 5 节)。这是因为 **structured 泄露面 ≥ pixels**(免疫遮挡、穿透打码、能拉视口外/隐藏节点),"最便宜=最低门槛"是危险倒挂。

- **visibility 并入 `pixels.capture_mode`** ∈ {foreground_copyfromscreen, background_printwindow, background_graphicscapture}。foreground/background 这对值只在涉及屏幕合成时有区别;structured 提取与前后台无关,**不冒用"后台静默=更高权限"的静默捕获预算**(它另走"深度读取"授权)。capture_mode ∈ background_* 时触发后台静默提权门(第 5、10 节)。

### 2.2 target、2.3 when×validity、2.4 validity 见第 3、7、8 节(避免重复)

### 2.5 sink:剥离偷藏的模态转换,拆两个正交子维度

原 `analyzed`(像素→OCR→只回结构化)偷偷夹带 pixels→text 模态转换,与 modality=ocr 重叠、组合时重复 OCR。修法:模态转换还给 modality 轴。
```
sink.processing    : none | diff | redact | summarize
sink.return_shape  : raw_to_context | predicate_gated | result_only | summary_only | human_first
```
- 原 `analyzed` = processing∈{diff,redact} + return_shape=result_only;其中的 OCR 不再由 sink 自己做——需要文本就显式 modality=ocr。于是 `modality=ocr + return_shape=result_only` 含义唯一:OCR 一次,只回文本不回图,无重复 OCR。
- return_shape 是**单调放行链**,只能向更受限升级:raw_to_context → predicate_gated → result_only → summary_only → human_first。

### 2.6 redact:用户参数双实现 + 强制脱敏地板(焊死安全接缝)

用户可填的 `redact` 由 modality 锁定可填字段(判别联合):
```
modality=pixels      → redact.pixel{ rects | auto_ocr_pii }
modality=structured  → redact.content{ selectors | regex | field_names }
modality=ocr         → redact.content{ regex | field_names }
```
structured 分支若收到 pixel rect,**契约校验期 fail-closed 报非法组合**,而非运行期静默丢弃。

**关键澄清(v2 新增):** 上面是**用户可选的附加脱敏**。在它之下还有一道**不可关闭的强制脱敏地板**——结构内容脱敏器(structural redactor),见第 6 节。用户 redact 是"额外再挡",强制地板是"无论如何先挡"。两者都汇入回执单一 `redaction` 视图。

### 2.7 轴兼容约束矩阵(契约层强制,非法即拒)

| 约束 | 规则 |
|---|---|
| visibility × modality | capture_mode 仅 pixels 可填;structured/ocr 填写即非法 |
| redact × modality | pixel rect 仅 pixels;content 仅 structured/ocr;错配 fail-closed |
| scale/stamp × modality | 仅 pixels;纯文本输出填写即非法(空操作) |
| validity.script × modality | 判别集随 modality 锁定(第 8 节);无判据可跑→strict 自动降 narrator |
| target=screen/region × element | screen/region 分支不接受 element 字段;screen+element 不可表达 |
| occlusion × by:ocr | `ocr + require_complete` 非法(锚点必在像素里,遮挡区无文字) |
| modality=structured × ocr 寻址 | OCR 锚点不产结构,非法组合 |

> 归因:judgment "modality 是隐藏主轴、其余派生" 与判别联合化是标准类型工程(illegal states unrepresentable);"按泄露面而非 token 成本排序模态默认"是这套 AI 工具论的塑造——它把"AI 系统性被推向最危险路径"视为设计缺陷而非性能优化。

## 3. 目标寻址 Mini-DSL

**职责:** 把语义意图解析为三类真实句柄之一,并把"为达成寻址付出的副作用"(夺焦、连拍、提前)如实回流门控与回执。

### 3.1 五层语法(判别联合,层级单调收窄 screen ⊃ app ⊃ window ⊃ element)

```
target =
  | screen                                   # 主屏全屏,无候选/无遮挡概念
  | region{ rect, space:primary_px|virtual_desktop_px|window_client_dip, dpi_aware }
  | active                                   # = frontmost window 便捷别名
  | app{ selector, candidate_policy, occlusion_policy }
  | window{ handle | cdp_target, occlusion_policy }
  | element{ within:(app|window), by, query, candidate_policy }
```
**app 选择器:** `proc(/regex/)` | `title(/regex/)` | `frontmost` | `handle(<token>)`
**surface 选择器(承认本机命名分裂):** `window(hwnd|index)` | `tab(driver:control_chrome, tab_id:int)` | `tab(driver:cic, device_id, tab_ref)` | `cdp(endpoint, target_id)`(仅端点存在时) | `tab(...) + route{ matcher:/hash|path/, settle:<pred> }`(SPA)
**element 选择器(`by` = 寻址机制轴,经决策表派生而非等同后端/模态):**
```
dom(css, pierce:[shadow? same_origin_iframe?]?)  | uia(AutomationId=.. | Name=/re/ | ControlType=.. 路径)  | ocr(anchor:/text/, side, span)
```
**candidate_policy:** `frontmost`(默认) | `most_recent` | `all` | `ask_user` | `fail`
**occlusion_policy:** `require_complete` | `offscreen_render` | `structured_fallback` | `bring_to_front` | `partial_ok_declared`(默认)

### 3.2 寻址 × 模态 × 遮挡 × 夺焦决策表

| element.by | 蕴含后端 | 默认→可覆盖模态 | 遮挡处置 | 夺焦 |
|---|---|---|---|---|
| dom(control_chrome,活动标签) | execute_javascript | structured→ocr/pixels | 免疫 | 否 |
| dom(control_chrome,非活动标签) | switch_to_tab+JS | structured | 免疫 | **是→focus_state.changed** |
| dom(cic, ref) | find/get_page_text | structured | 免疫 | 否(后台可读) |
| dom(cdp,target) | CDP | structured/pixels | 离屏可截 | 否 |
| uia(path) | UIAutomation | structured→ocr | 免疫(读控件树) | 否(可后台静默) |
| ocr(anchor) | 先取 pixels 再 OCR | ocr/pixels(**不可 structured**) | 与 require_complete 互斥 | 取决像素来源 |
| (无 element) | CopyFromScreen/PrintWindow/mcp | pixels→ocr | 前台受遮挡;PrintWindow 离屏(GPU 可能黑帧) | CopyFromScreen 是 |

**解析期非法组合(直接拒):** `ocr+require_complete` · `dom+cross_origin_iframe`(同源策略不可达,回落 uia/pixels) · `background_silent + dom(control_chrome,非活动标签) + 无CDP`(必夺焦,违反静默) · `modality:structured + ocr 寻址`。

### 3.3 硬骨头补全

- **稳定句柄(带 epoch 复合令牌,非裸 HWND):** `handle={kind, raw, fingerprint:{proc,title_re,url_prefix|uia_runtimeid}, epoch_token, invalidates_on:[window_closed,navigated,tab_closed,process_exited]}`。复用前用廉价只读探针(EnumWindows/list_tabs/document.location)比对指纹;不符即 epoch 失效→回执报"句柄失效,已重解析",**绝不复用陈旧坐标/tab_id**。
- **CDP targetId 不存在的现实:** 解析器先探测哪个驱动在线(list_tabs / list_connected_browsers),targetId 降级为"端点存在才用,否则回落 tab_id+在页 JS",回执 `source.surface_id` 标明实际句柄命名。
- **多实例消歧:** `all` 策略对 N 实例 = N 次独立捕获,产出 `candidate_count` 回流门控,逐次过 ε_pool 与 count 闸门;不够则整体 fail-closed 并列"解析出 N 个,预算只够 K 个"。
- **SPA 路由当"页面":** route 是界面选择器一等维度,`settle` 谓词等路由+异步内容稳定才触发 when;不稳定即阻塞,超时 fail-closed。"页面≠窗口≠标签"写进解析层语义。
- **shadow/iframe:** `pierce:[shadow]` 用 composed-path 穿透;`pierce:[same_origin_iframe]` 递归;跨域 iframe 标 `unreachable_cross_origin`→回落 uia/pixels 申报。
- **多显示器/DPI:** region 强制带 space 标注;解析层持每显示器 (origin,scale) 负责三套坐标系换算;mcp_fullscreen 只接受 primary_px,其余强制落 os_window 并申报。
- **bring_to_front = 不可收束副作用:** 仅在 foreground 且 sink≠background 时允许,执行前过安全闸门;回执 `completeness.irreversible_side_effects:[brought_to_front{window}]` 如实申报。诚实边界:收束只能作废未入上下文缓冲,**不能撤销已发生的物理夺焦**。

> 归因:DSL 收敛到三类真实句柄、CDP targetId 不存在的回落、坐标系换算、shadow/iframe 穿透,全是本机实测逼出的标准工程;"夺焦/连拍/提前等副作用必须如实回流"是 AI 工具论塑造——它要求寻址语言对自己的代价透明。

## 5. 双闸门 + 收束门控管线(按泄露面重排授权)

**一条流水线,两道独立闸门 + 收束。**

### 5.1 入口闸门(授权件)
实例化八字段授权件 ⟨主 受 动 址 限 时 证 转⟩ → 验签 ∧ 在窗 ∧ 未撤销?否则 fail-closed → 异常库匹配(只读窗口标题/进程/频次,**不读像素**)→ 直接/延迟/送分诊。

**"动"字段按泄露面区分动作权(v2 焊死):**
- `capture_visible`(pixels 前台、ocr 本地、所见即所得)= 基础授权位。
- `extract_structure`(structured 提取隐藏/视口外/password 邻域节点)= **独立"深度读取"授权位,默认禁用、每次授权**,类比后台静默。
- `background_silent`(capture_mode ∈ background_*)= **独立授权模式,默认禁用,不可由会话内任何同意累加,单次单窗口、到期即焚**。
- `allow_egress`(数据离机,见第 10 节)= 独立授权位。

转授单调律对四种动作权**分别**生效:转授只能逐坐标收窄;放宽必须回根(子代理要更宽范围须回用户重授)。

### 5.2 后台静默三处硬联动(兑现"更高权限")
1. **异常库前置:** 捕获前只读窗口标题/进程名匹配异常库;password manager / banking / auth / wallet 类进程命中即 fail-closed,**连授权问询都不发**。
2. **ε_pool 加权:** 后台静默按更高权重扣预算;与深度读取叠加时**权重相乘**。
3. **SILENT 强制申报:** 回执 visibility=background_silent 置顶显著标注;candidate_resolution 记录"此窗口用户未主动调出",使 AI 无法把后台来源误当前台所见。
4. 收束延伸:后台静默缓冲在入上下文前若用户切走/锁屏,**原子作废**。

### 5.3 ε_pool(会话级隐私预算,计量单位改版)
须独立授予,不能由单次同意累加(防连拍拼出完整工作流)。**计量单位从"捕获次数"改为"泄露面加权信息量"**(焊死接缝):pixels 可见区 / ocr 本地 = 1× 基准;structured 可见节点按提取字符/节点数折算;structured 含 offscreen/hidden 与 background_silent = 高倍率;叠加相乘。整页 innerText 一次扣减显著高于单张可见区截图。

### 5.4 收束耦合
已截未入上下文期间,任一前置授权降级/撤销 → **原子作废已截缓冲 + 取消同链排队截图**。安全闸门主动 block 复用同一作废原语。

> 归因:八字段授权件、转授单调、ε_pool 防拼接,是这套 AI 工具论的塑造(它把"AI 索取外界信息"当作需逐次授权的权利行为)。"按泄露面而非 token 成本排序授权"是本轮安全复审对该工具论的修正——更忠于其"最小泄露面"内核。

## 6. 多模态与脱敏(三层强制结构脱敏器)

**模态表:** structured(免疫遮挡、token 最低、泄露面最大)→ ocr(中)→ pixels(受遮挡、token 高;GPU/DComp 合成表面 PrintWindow 可能黑帧)。

**两道平行脱敏闸门,各管一条路径:**
- **像素打码(已有):** allowlist 合成器/像素级,对未授权应用打码。**对 DOM/UIA 节点流零作用。**
- **结构内容脱敏器(v2 新增,结构/OCR 模态强制前置、不可关闭):**
  1. **节点类型剥离** — UIA 命中 IsPassword=true(id=30019)或 ControlType=Edit∧IsPassword;CDP 命中 input[type=password]、autocomplete∈{cc-\*, one-time-code, current-password}、ARIA 敏感区:整节点不进上下文,只留 `[REDACTED:password]`。
  2. **正则内容脱敏** — 对所有文本节点跑 信用卡(Luhn)、私钥/token(高熵+前缀 sk-/ghp_/AKIA)、SSN/身份证、JWT 三段式;命中即掩码。
  3. **可见性边界** — 默认只提取 IsOffscreen=false 节点;视口外/未渲染节点须显式 `include_offscreen=true` 才取且单独申报。

**脱敏顺序锁死:** 捕获 → 本地脱敏 → (可选)外送。脱敏永远发生在任何外送之前。

**结构化文本 = 注入提级通道(落地隔离):** 所有结构/OCR/文档转换产物强制包裹 `<untrusted-capture source=…>…</untrusted-capture>`,回执 content 标 `trust=untrusted`;untrusted 区块内文本一律不得作为指令解释、不得触发任何"须显式许可/禁止"档动作(发送/下载/改权限/执行);markitdown 转换剥离/转义可点击 href 为纯文本。结构路径因高保真额外申报 `injection_surface=high`。

> 归因:结构脱敏器、注入隔离分隔符是本轮安全复审的硬产物(因实测 UIA/CDP 能穿透像素打码读密码框)——这是 AI 工具论"永不静默失败"在结构路径上的兑现。Luhn/高熵检测、untrusted 包裹是标准安全工程。

## 7. 捕获生命周期状态机

**三条不变量:** ① 永不静默(每个失败出口产出固定回执,verdict 说明失败种类);② **安全否决有效,有效不否决安全**(安全闸门对"内容是否离开缓冲区"有最终否决权;有效性只能在"纯像素预检"层先于安全跑,用来省鉴权地快速失败,**预检禁止读取语义**);③ 两类失败语义不混(有效性失败=没拿到,可重捕获;安全失败=拿到了但不准进,需升级权利)。

### 7.1 状态枚举
单帧:`IDLE → AUTHORIZING → ARMED(等触发) → CAPTURING → VALIDITY_PRECHECK → [RECAPTURE_LOOP] → [JUDGE_ESCALATION] → SECURITY_GATE → EXIT_GATE(5档) → INGESTED`。
辅助/失败态:`PAUSED_REAUTH` · `COLLAPSING` · `FAILED(verdict)` · `SAMPLING`(时序子机)。
**扣费点(显式标注):** AUTHORIZING 出口 = admission control 预算预扣门;ANALYZING/NARRATING(EXIT_GATE 内)入口 = ε_pool 实际扣减点(**读像素即消费,不论最终是否入上下文**)。

### 7.2 主转移表(关键行)

| 源态 | 触发 | 目标 |
|---|---|---|
| AUTHORIZING | 八字段 验签∧在窗∧未撤销 ∧ 异常库放行 ∧ **预估≤剩余预算** | ARMED |
| AUTHORIZING | 预估 token/ε 超剩余 | FAILED(insufficient_budget,快门前未截) |
| CAPTURING | 后端返回帧(任意质量) | VALIDITY_PRECHECK |
| CAPTURING | 后端异常(句柄失效/PrintWindow黑帧) | 回退链(7.4),耗尽→FAILED(capture_error) |
| VALIDITY_PRECHECK | 纯像素统计判 rendered_nonblank ∧ 类(a)谓词满足 | SECURITY_GATE |
| VALIDITY_PRECHECK | blank/stale/loading 或 类(a)谓词不满足 | RECAPTURE_LOOP(轴A) |
| VALIDITY_PRECHECK | uncertain(脚本判不准) | JUDGE_ESCALATION(轴B) |
| RECAPTURE_LOOP | 次数<max_reattempts(默认3,退避250/750/1500ms) | CAPTURING(重走,重判新帧) |
| RECAPTURE_LOOP | 耗尽仍未就绪 | FAILED(timeout_unready) |
| JUDGE_ESCALATION | 升级判官(脚本→子代理→用户)某级判 rendered | SECURITY_GATE |
| JUDGE_ESCALATION | 某级判 blank/stale | RECAPTURE_LOOP(回轴A) |
| JUDGE_ESCALATION | 用户级仍 uncertain/超时 | FAILED(unverifiable) |
| SECURITY_GATE | 分诊(机器→子代理→人类)pass | EXIT_GATE |
| SECURITY_GATE | block(命中未授权/异常) | COLLAPSING→FAILED(blocked,appealable?) |
| SECURITY_GATE | 人类级超时 | FAILED(denied,fail-closed) |
| EXIT_GATE | 按 sink 放行,含语义期望谓词校验 | INGESTED 或 FAILED(expectation_violated) |
| 任意态(ARMED..EXIT_GATE) | 前置授权降级/撤销 | COLLAPSING |
| COLLAPSING | 原子作废缓冲∧取消同链排队 | FAILED(collapsed) 或 PAUSED_REAUTH(时序) |

### 7.3 两个正交循环轴(解决重试歧义)
- **轴 A 重捕获循环(liveness):** 针对 blank/stale/loading 与类(a)谓词不满足。固定退避重捕获(max_reattempts=3),**每次重新捕获新帧并脚本重判**,不重判旧帧。耗尽→FAILED(timeout_unready)。
- **轴 B 判官升级阶梯(confidence):** 仅针对 uncertain。把**同一帧**交更强判官 脚本→转述子代理→用户,每级 1 次,**不重捕获**。用户级仍不定→FAILED(unverifiable)。
两轴触发器互斥:verdict∈{blank,stale,loading}→A;uncertain→B。只有连续重捕获后仍 uncertain 或 validity=strict 才从 A 切 B。

### 7.4 GPU/DComp 黑帧回退链与"真黑 vs 假黑"判别
单帧绝对亮度不可靠(实测:纯黑帧 mean_lum=0/dominant_bin=1.0,暗色主题 UI 同样 mean_lum 极低)。**三信号合议:** ① 跨后端交叉验证(PrintWindow 黑帧时立即取 structured 层;结构丰富而像素全黑→判定 DComp 合成表面黑帧,触发回退;结构也空→存疑);② 直方图形状(真黑=单峰 δ dominant_bin≈1.0 无次峰;暗色 UI=低位多峰,dominant_bin<0.95 有次峰);③ 全零 RGB+alpha(PrintWindow 失败常返 alpha=0,与真黑底 alpha=255 可分)。
**回退链(锁定):** PrintWindow(PW_RENDERFULLCONTENT) 黑帧 → Graphics.Capture(WGC,对 DComp 友好) → 可见时前台 CopyFromScreen(须提到前台,sink 申报) → 全失 → FAILED(blank_unrecoverable),回执标注"结构层是否也空"供 AI 区分真黑底与真失败。

### 7.5 期望谓词机制(破"校验需读语义 vs 预检禁读语义"死锁)
分两类、放闸门两侧:
- **类(a) 结构无关谓词**(differs_from_last 哈希、min_entropy、has_text 布尔——OCR 只返回有无字不返回字):在 VALIDITY_PRECHECK 求值,参与轴 A。
- **类(b) 语义谓词**(contains 正则、matches_schema、is_chart):移到 EXIT_GATE 的 result_only 档求值——语义校验本身 = 一次受控消费(像素→OCR→只回谓词真假+命中片段)。
**when×validity 默认推导:** when 携带谓词(on_appear/on_change)且 validity=none 时,自动复制触发谓词为 validity.expected_predicate 并把强度提升 basic(可显式覆盖回 none),堵触发器抖动把未就绪画面当成功的漏洞。
**无期望谓词时:** validity 保证级别显式降为 `liveness_only`(仅非空白),回执 `expectation:{declared:null, guarantee:'liveness_only'}`,明确告知 AI"这帧非空白,但无人保证内容正确或新鲜"。

### 7.6 安全闸门拦截处置
三出口:pass | escalate(机器→子代理→人类,人类级超时=默认拒绝) | block。block:① 原子作废缓冲;② 若因命中异常库,记一次频次(供升频触发更严分诊);③ 申报 `blocked{reason, gate:'value', appealable}`——appealable=true(仅缺 ε 授予)告知可走人级补预算重试;appealable=false(硬命中未授权应用)明确不可由 AI 自授重试。

> 归因:两正交循环轴、安全否决有效的顺序、期望谓词两类分置,是这套 AI 工具论"永不返回半成品"逼出的状态机硬产物。黑帧三信号合议、回退链是实测逼出的标准图形工程。

## 8. 有效性闸门判别集(随 modality 分派)

validity 保留三级链(script→narrator→user)作"强度"轴,与 modality 正交;script 级判别器实现声明为 modality 的函数:
```
pixels      → blank | monochrome | stale_frame | low_entropy
structured  → empty_dom | placeholder_only | innertext_blank | uia_root_only
ocr         → ocr_empty | confidence_below_threshold
```
铁律补强:strict 在某 modality 下无可跑 script 判据时**自动降级 narrator 而非静默通过**。"全白=未渲染"只对 pixels 成立这一限制,由此被结构化圈进 pixels 分支,不再越界误报。

> 归因:判别集随 modality 分派是参数正交性硬化的直接结论(标准工程);"无判据可跑则降级而非静默放过"是 AI 工具论塑造。

## 9. 固定回执信封(可靠的核心,字段统一)

每次捕获无论成败都带,**废除孤立的 `masked_regions`(它在结构路径恒为"无",制造"本次无脱敏"的错误安全感)**,统一为单一视图:

```
content              : 包裹 <untrusted-capture> 的产物;trust=untrusted/trusted
source               : { app, window, surface_id, element_path, candidate_resolution }
modality             : structured | ocr | pixels
timestamp
focus_state          : unchanged | changed_to{tab_id|window}
completeness:
  occluded           : { yes/no, what }
  validity_verdict   : rendered | blank | stale | loading | uncertain | timeout_unready | unverifiable
  expectation        : { declared, evaluated_at:pre_gate|post_gate, verdict:satisfied|violated|unverifiable, guarantee }
  redaction          : { pixel_masked_regions, structural_nodes_stripped, content_patterns_masked, offscreen_policy }
  injection_surface  : low | high
  irreversible_side_effects : [ brought_to_front{window}, ... ]
  candidate_count    : N(解析基数,>1 时逐一过预算)
residency            : { processing: local|cloud, data_left_device:bool, what_left }
budget               : { epsilon_spent_this_capture, epsilon_pool_remaining(加权单位), tokens, shared_capture:bool }
```

任一种脱敏发生即在唯一 `redaction` 字段反映,消除"像素闸门未触发=无脱敏"的歧义。至此结构提取与后台静默两条能力轴的泄露面都进入闸门视野并对 AI 可申报。

> 归因:固定回执信封(无论成败都申报)是这套 AI 工具论的立身核心。字段合并、residency/injection_surface 是三面硬化的并集收口。

## 10. 时序/视频模态

```
clip{duration,fps,trigger_start,trigger_stop} | sample{interval,max_frames,stop_on:pred} | watch_until{pred,then:grab|clip}
```
**铁律:** 视频几乎永不以帧序列进上下文;时序捕获默认 sink 强制 `summary_only`(narrated 子代理看完只回自然语言)或 `keyframes`(帧间 diff 只抽变化帧)。

**子状态机 SAMPLING,三并列停止门**(任一先到即停并申报哪个先到):`stop_on_pred` | `stop_on_budget`(max_frames ∨ ε_pool ∨ token 任一耗尽) | `stop_on_timeout`(墙钟/watch 窗口)。
- **长窗口授权冲突:** watch/sample 授权件携 `watch_window_ttl`,每帧前重验签∧在窗;中途过期→**不静默停止**,转 PAUSED_REAUTH,已采帧保留,申报"授权过期,已采 N 帧,需重授续采或就此收束",人级裁。
- **去重:** 会话级滚动 perceptual-hash 环,汉明距离≤5 视为重复;重复帧不计 max_frames、不入 sink,**但真实快门数仍按加权计 ε_pool**(堵"去重免费连拍拼工作流")。
- **并发合并:** 相同 ⟨target,modality,validity⟩ 且时间窗重叠的请求,后到者 attach 在途捕获,共享一次快门一次鉴权,回执 `shared_capture=true`。

> 归因:"视频永不以帧序列进上下文、默认转述/抽关键帧"是 AI 工具论塑造(对 token 与隐私的双重纪律);三停止门、感知哈希去重是标准工程。

## 11. 安全/隐私/数据驻留规则(集中条款)

1. **结构泄露面 ≥ 像素** → structured 深度读取须比 pixels 截图更高授权(第 5、6 节)。
2. **强制结构脱敏器不可关闭** + 脱敏顺序锁死(捕获→本地脱敏→外送)(第 6 节)。
3. **结构/OCR 产物 = 不可信** → untrusted 包裹、不得当指令、剥离可执行 href(第 6 节)。
4. **后台静默三处硬联动** + 单次单窗口到期即焚 + 不可累加(第 5.2 节)。
5. **数据驻留三规则(v2):**
   - 默认 OCR 锁死本机 WinRT(实测 en-US/ja/zh-Hans-CN 离线可达);云 OCR 须独立 `allow_egress` 授权,回执 `data_left_device=true`。
   - narrated 子代理若为云模型,读原图 = 外送像素,须同档 `allow_egress`,且**子代理只能收到已脱敏图,不得收原图**。
   - 回执 `residency` 字段强制申报任何离机处理。
6. **ε_pool 按泄露面加权** + 读图瞬间扣减(非入上下文瞬间)(第 5.3、7.1 节)。
7. **异常库只读** 窗口标题/进程/频次,不读像素;后台静默捕获前置匹配。

> 归因:整节是本轮安全复审推翻"旧前提(捕获=像素=所见即所得)"后的产物——它是这套 AI 工具论"最小泄露面+永不静默"内核被新能力(结构提取、后台静默、云外送)激活后的必然兑现。Luhn/高熵/感知哈希/同源策略是标准安全工程。

## 收口:v2 相对 v1 的实质变更清单
1. 参数面 7 轴 → 5 正交核心轴 + 3 组模态私有子参数(判别联合)。
2. 模态默认从"最便宜层"翻转为"最小泄露面层"。
3. 新增不可关闭的结构脱敏器,与像素打码平行。
4. extract_structure / background_silent / allow_egress 三种动作权独立授权,转授单调分别生效。
5. ε_pool 计量从"次数"改为"泄露面加权信息量",扣减点前移到读图瞬间。
6. 状态机拆出轴A(重捕获)/轴B(判官升级)两正交循环 + GPU 黑帧三信号回退链 + 期望谓词两类分置。
7. 回执信封废除 masked_regions,统一 redaction/residency/injection_surface/expectation/candidate_count。
8. 时序捕获定义独立 SAMPLING 子机(三停止门 + PAUSED_REAUTH + 加权去重 + 并发合并)。
