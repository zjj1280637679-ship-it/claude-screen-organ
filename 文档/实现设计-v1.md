> 本文档取代《设计规范-v2》作为**实施契约**；v2 降级为风险与陷阱参考库（黑帧、句柄失效、注入包裹、夺焦申报等条目仍然有效，实现时查阅）。
> 设计依据：2026-06-11 四路调研（Claude Code 插件规范 / 8+ 成熟截图 MCP 项目 / Windows 捕获技术栈 / screen-guardian 先行项目代码实证）+ 本机环境基线。

## 1. 定位与差异化

**一句话**：给 Claude Code 的 Windows 窗口级视觉感知插件——官方 computer-use 截的是"整个桌面"，本插件补"按窗口寻址、不抢焦点、读得出文字"的缺口。

与官方 computer-use 工具的分工（对照表）：

| 场景 | computer-use | screen-organ |
|---|---|---|
| 全屏看一眼 | ✓ screenshot | ✓（capture_screen，作为无 computer-use 环境的兜底） |
| 指定窗口（不置前、不打扰用户） | ✗ | ✓ capture_window quiet 模式 |
| 被遮挡/后台窗口 | ✗ | ✓（PrintWindow→WGC 降级链） |
| 窗口清单与状态 | ✗ | ✓ list_windows |
| 从窗口提取文字（OCR/UIA） | ✗ | ✓ read_text（密码框强制遮罩） |
| 点击/输入 | ✓ | ✗（明确不做，截图永远是证据不是授权） |

设计基因（取舍来源）：
- **工具面**：3-6 个正交工具（snap-happy 极简 + screen-guardian "44 工具收敛到 3 门面"的教训）；
- **寻址**：Peekaboo 统一寻址思想，Windows 化为 hwnd/标题子串/进程名（中文系统必须有 HWND 这种语言无关寻址）；
- **返回**：Playwright MCP 模式——默认落盘返回路径，Claude 用 Read 读图（绕开 MCP 25k token/1MB 响应限制）；inline 作可选项，T0 实测后定默认；
- **可靠性**：screen-guardian 实证机制整体移植（四指标黑帧检测、客户区单独检测、bbox 身份探针、决策菜单而非拒绝）；
- **诚实**：回执信封如实申报 method/verdict/缺了什么——"永不静默失败、永不返回半成品"是从理论检验里唯一保留的铁律。

## 2. 架构

### 2.1 进程模型
单个 Python MCP server（FastMCP，stdio）。进程启动第一件事（import 任何截图库之前）：
```python
ctypes.windll.user32.SetProcessDpiAwarenessContext(-4)  # PerMonitorV2，失败降级 shcore(2)，再降 SetProcessDPIAware
```
全程物理像素坐标系。`PYTHONUTF8=1` 防中文系统 cp936 污染 stdio JSON-RPC。

### 2.2 捕获降级链（核心）
```
capture_window(target, mode):
  mode=foreground: SetForegroundWindow → 等待渲染 → mss 按 DWMWA_EXTENDED_FRAME_BOUNDS 裁剪（最稳，但夺焦，须显式选择）
  mode=quiet (默认):
    ① PrintWindow + PW_RENDERFULLCONTENT
    ② 四指标黑帧检测 + 客户区单独检测 → 通过则返回
    ③ 失败 → windows-capture (WGC)：起会话→取首帧→立即停（黄边只闪现，文档如实告知）
    ④ 仍失败且窗口可见 → mss 按窗口矩形裁屏 + 5 点 bbox 身份探针（match≥0.6 才放行）
    ⑤ 全失败 → 回执 verdict=failed + 决策菜单（建议 mode=foreground 或 wait 参数）
  最小化窗口：显式报告 minimized，不静默返黑图；可选 restore_if_minimized=true（SW_SHOWNOACTIVATE→截→还原）
```
已知引擎级限制（文档化，不试图绕过）：完全被遮挡的 Chromium 窗口因 occlusion 节流可能得冻结旧帧 → 回执 warning + 建议置前。

### 2.3 质量检测（移植 screen-guardian 实证阈值）
- 缩到长边 384px 灰度，算亮度/对比度(stddev)/FIND_EDGES 边缘均值/直方图熵；
- likely_blank = uniform_dark(亮度≤3∧对比≤1∧熵≤0.1) ∨ uniform_light(≥252∧≤1∧≤0.1) ∨ low_information(对比≤3∧边缘≤1.2∧熵≤0.45) ∨ bright_low_information(≥252∧≤6∧≤0.2)；
- 窗口捕获必须把 client rect 裁出单独跑指标（整图被标题栏拉高会漏检）；
- 纯色合法界面会误报 → 屏幕/区域捕获默认不开 blank 重试，仅窗口捕获默认开（重试 2 次 / 250ms）。

### 2.4 窗口枚举
EnumWindows + IsWindowVisible + 非空标题 + DWMWA_CLOAKED(14) 过滤 + Raymond Chen Alt-Tab 算法（GA_ROOTOWNER/GetLastActivePopup，WS_EX_TOOLWINDOW 排除、WS_EX_APPWINDOW 纳入）；UWP 窗口穿透 ApplicationFrameHost 取真实进程；每窗附 5 点遮挡探针结果（possibly_occluded）。

## 3. 工具面（6 个，名字即权限粒度）

高风险动作拆成独立工具，让 Claude Code 原生的逐工具权限提示天然充当独立授权位（零成本实现"按泄露面分级授权"）。

| 工具 | 作用 | 风险级 |
|---|---|---|
| `screen_info()` | 显示器/能力/捕获后端健康 + recommended_next，不截图 | 只读 |
| `list_windows(filter?)` | Alt-Tab 视角窗口清单：hwnd/title/process/rect/minimized/occluded/monitor | 只读（标题可能含敏感词，回执注明） |
| `capture_screen(monitor?, region?, ...)` | 全屏/区域截图 | 中 |
| `capture_window(target, mode=quiet, ...)` | 单窗口截图，默认不夺焦 | 中（quiet 可拍到用户没在看的窗口） |
| `read_text(target, engine=auto, region?)` | WinRT OCR（zh-CN/en 已就绪）或 UIA 文本提取 | 高（穿透视觉，输出强制 untrusted 包裹 + 密码遮罩） |
| `wait_capture(target, until=stable\|change\|window_appears, timeout≤30s)` | 时序捕获（等渲染稳定/等变化/等窗口出现） | 中（有界：硬上限 30s/50 帧） |

通用参数（capture 类）：`delay_ms`、`wait_stable`（帧差≤1.5 连续 2 帧）、`scale`（默认长边 1568px）、`format`（png 默认/jpeg）、`return_mode`（path 默认/inline/both，T0 后定）。

寻址 `target`：`{hwnd: 123}` 精确 ｜ `{title: "记事本"}` 子串模糊 ｜ `{process: "notepad.exe"}` ｜ 多匹配时返回候选列表要求二选（不自动拍第一个）。

### 回执信封（每次调用必返，约 12 字段，精简——screen-guardian 的啰嗦 JSON 是反面教材）
```json
{
  "ok": true, "verdict": "ok | blank_suspected | occluded_risk | identity_mismatch | frozen_frame_risk | refused_sensitive | failed",
  "method": "printwindow | wgc | screen_crop | mss",
  "source": {"kind": "window", "hwnd": 123, "title": "...", "process": "...", "minimized": false},
  "file": {"path": "...", "w": 1568, "h": 882, "bytes": 123456},
  "redaction": {"password_fields_masked": 2, "denylist_hit": null},
  "trust": "untrusted",
  "warnings": ["..."], 
  "next_actions": [{"hint": "窗口疑似空白，建议", "params": {"mode": "foreground"}}],
  "timing_ms": 240
}
```
决策菜单模式：守卫触发时不拒绝，返回 capture_deferred + 可直接复用的重试参数。

## 4. 安全与隐私

1. **敏感窗口黑名单**（进程名+标题正则：1password/keepass/bitwarden/authy/钱包/UAC consent.exe/Windows 安全中心…）：命中默认拒绝并回执 refused_sensitive；显式 `acknowledge_sensitive=true` 才放行（仍走遮罩）。清单放配置文件，用户可增删。
2. **密码框遮罩**：read_text 的 UIA 路径剥离 IsPassword=true 节点（UIA_IsPasswordPropertyId=30019）；capture 路径对已知密码框 BoundingRectangle 打码（尽力而为，回执如实申报 what_left——不承诺"绝对脱敏"，那是 v2 规范里被证伪的"名不副实"）。
3. **注入防御**：OCR/UIA 文本一律包 `<untrusted-capture>` 并标 trust=untrusted（缓解措施而非机制保证，文档如实说明）。
4. **存储生命周期**：截图存 `%LOCALAPPDATA%\screen-organ\captures\`（装为插件后迁 `${CLAUDE_PLUGIN_DATA}`）；server 启动时清理 >24h 或超 200 张的旧文件；提供 `screen_info` 里报告当前占用。
5. **不做的事**：不点击不输入、无后台常驻调度、无隐藏上传、视频/帧序列永不直接进上下文（wait_capture 只返回最终帧+变化摘要）。

## 5. 打包（Claude Code 插件）

```
plugin/                          ← 插件根（英文路径，避免编码风险）
├── .claude-plugin/plugin.json   ← name/version/description + mcpServers 内联
├── mcp/
│   ├── server.py                ← FastMCP 入口
│   ├── capture.py  wininfo.py  quality.py  textread.py  privacy.py  store.py
├── skills/screen-capture/SKILL.md  ← 何时用哪个工具的工作流指引（先 list 后 capture、黑帧怎么办）
└── tests/                       ← pytest（L1）+ 场景 harness（L2）
```
- mcpServers command：开发期直接 `python ${CLAUDE_PLUGIN_ROOT}/mcp/server.py`（依赖装进系统 Python）；发布形态再评估 uv run + PEP 723（待测冷启动时延）。
- 组件目录在插件根，**不在** .claude-plugin/ 内（调研确认的高频错误）。
- 本地测试：`claude --plugin-dir` 装载，`/reload-plugins` 重载；MCP server 代码改动后是否需要重启会话待 T0 实测。

## 6. 测试策略（三层回路）

- **L1 单元**（毫秒级，改代码即跑）：pytest + FastMCP in-memory client 直调工具断言信封字段；质量检测/枚举/遮罩用合成图与 tkinter 窗口测。
- **L2 场景 harness**（分钟级）：脚本启动真实应用+tkinter 测试窗，跑验收矩阵（§7），断言"非黑帧/身份验证/错误语义/耗时预算"，每次提交跑。tkinter 自造已知内容窗口（已知文本→OCR 比对；Entry(show='*')→遮罩验证；定时变色→wait_capture 验证）是从 screen-guardian 学的最巧一招。
- **L3 端到端**：`claude -p --plugin-dir plugin "列出窗口并截记事本"` headless 验证插件装载/权限弹窗/Claude 实际调用路径；最后交互式会话人工验收。

### T0 前置实测（动工前定三个默认值）
1. **图像返回通道**：inline base64 vs path+Read 的真实 token 成本（claude -p --output-format json 读 usage），定 return_mode 默认；
2. **PrintWindow/WGC 逐应用表现**：Notepad/Chrome/Electron/UWP 前台后台各跑一遍，定降级链顺序与阈值；
3. **MCP 启动**：python 直启 vs uv run 冷启动时延，/reload-plugins 是否重启 server 进程。

## 7. 验收矩阵（"成熟"的定义）

每格三种合法结果：**好图**（非黑帧+身份验证通过）/ **诚实降级**（明确 verdict+可执行建议）/ **明确拒绝**（refused_sensitive 等）。非法结果只有一种：静默的错图/黑图。性能预算：单次捕获 ≤2s（wait 类除外）。

| 应用 \ 状态 | 前台 | 部分遮挡 | 完全遮挡 | 最小化 | quiet 不夺焦 |
|---|---|---|---|---|---|
| 记事本 (GDI) | S1 | S2 | S3 | S4 | S5 |
| Chrome (GPU) | S6 | S7 | S8(冻结帧风险) | S9 | S10 |
| Claude/VSCode (Electron) | S11 | S12 | — | — | S13 |
| 设置/计算器 (UWP) | S14 | — | — | — | S15 |
| 资源管理器 | S16 | — | — | — | — |

专项场景：S17 全屏截图｜S18 区域截图｜S19 OCR 中文+英文已知文本比对｜S20 UIA 文本提取｜S21 密码框遮罩（tkinter show='*'）｜S22 敏感窗口黑名单拒绝｜S23 多匹配寻址歧义→候选列表｜S24 不存在的窗口→failed 语义｜S25 wait_capture 等 tkinter 变色｜S26 连续 20 次调用稳定性+文件清理｜S27 scale/format 参数与 token 预算｜S28 list_windows 含 UWP 进程穿透。

全部通过（或诚实降级且建议可行）即判"成熟"；矩阵脚本化后作为回归基准。
