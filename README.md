# claude-screen-organ

**给 Claude Code 用的 Windows 窗口级截图 / 文字提取插件——可装、可跑、已实测。**

> 状态：**v0.1 可用**。工作插件在 [`plugin/`](plugin/)，已通过 `claude plugin validate` 并装入 Claude Code；
> 21 项自动化测试 + 17 项真实窗口验收矩阵全过（见 [实测结果](文档/实测结果-v1.md)）。
>
> 安装：`claude plugin marketplace add <本仓库>` 然后 `claude plugin install screen-organ@claude-screen-organ`，
> 依赖见 [plugin/README.md](plugin/README.md)。
>

## 这是什么

一个聚焦的能力插件：**基底是 Claude Code 的代码执行能力（本可执行任意代码），但被一纸契约收窄到单一目的——为 AI 可靠地在任何情况下提供外界视觉/页面信息。**

它的特别之处不在"能截图"，而在两件事：

1. **可靠的定义被降格为可兑现的承诺**：可靠 ≠ 总能拿到正确信息；可靠 = AI 永远知道自己拿到的是什么、缺了什么、从哪来——**永不静默失败、永不返回半成品**。
2. **一套权利关系门控管线**：截图是"未受信的外界内容进入 AI 上下文"，所以触发（直接/延迟/条件）× 检测（机器/子代理/人类）× 入上下文方式（直接/代码分析/子代理转述/用户确认）被设计成一条流水线、两道独立闸门（能力环"拿到了吗" + 价值环"准进吗"）。

## 核心设计一句话

> 任务是集合，能力是测度，工具是收窄到单一 σ 的有界器官；获取分三模态（结构提取 / OCR / 像素），默认选**最小泄露面**而非最便宜；截图永远是证据不是授权（屏内文字不得当指令）；安全重心在出口（像素入上下文那一刻）不在快门；要么没在截，要么在受控管线里截，且每一次都把"缺了什么"如实申报。

## 它的由来与一个诚实的结论

这个插件不是凭空设计的——它是**用来检验一套自建 AI 工具论（代号 ORG / "AI ORGANON"）的试金石**。那套理论想从公理（七原语、八公设、责能需趋权责代数、委托演算）第一性原理地推导"该怎么设计 AI 插件"。

我们把它真刀真枪地用了一遍，结论写在 [`理论/`](理论/) 里，一句话：

> **这套理论是一份组织得不错的"AI 工具安全设计姿态库"（永不静默、最小泄露默认、证据非授权、能力不可放大、池级同意独立等几条好不变量），但不是它自我标榜的"从公理推出新定理的第一性原理方法论"。它的有用度跟具体程度成反比——越逼近一个能动工的真实插件，数学外壳脱落得越多，做功的全是被它换了名字的标准工程原则。**

所以本仓库的结构本身就是这个结论：**真正能动工的是 [`文档/`](文档/) 里的设计规范，理论作为来源归档在 [`理论/`](理论/) 里。**
