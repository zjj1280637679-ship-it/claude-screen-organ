# 用插件检验理论：总结

> 命题：检验一套自称"第一性原理 AI 插件设计方法论"的理论（[ORG 评审](AI工具论-评审.md)），最硬的方式不是评论它，而是**用它设计一个真实插件，然后逐条看它在哪一层真的做了功**。这个截图插件就是那块试金石。

## 方法（防自我美化）

上一轮已抓到这套理论有"验证剧场"前科，而做检验的 Claude 与产生理论的是同一类人机回路，容易不自觉美化。所以：

1. 按理论设计插件，**每条设计决策填一张归因表**：公理做功 / 理论重述但归纳清晰 / 纯装饰 / 理论误导。
2. 一个独立的**对抗性怀疑者** agent，专门去**证伪**每一条"公理做功"声称——只要能找到一条纯标准工程（能力安全、最小权限、CaMeL 式控制流/数据流分离、运行时监控）到达同一设计的路径，那条就从"做功"降级为"重述"。

## 三次独立探针，同一个结论

| 探针 | 方法 | 落点 |
|---|---|---|
| ① 通读+复跑 | 读全部文档、逐行跑"机器验证" | "定理"多是换皮或重言；"机器验证"含恒真式/硬编码的验证剧场；闭合在作者-AI 回路 |
| ② 拿插件当试金石 | 按理论设计插件，逐决策归因 | 公理数学层零做功；怀疑者把 4 条"公理做功"证伪掉 3 条，只剩 SILENT 一条勉强保留为"清单级"增量 |
| ③ v2 打磨 | 把设计逼到工程完整 | 真正的设计功——找出 3 个致命矛盾、坐实像素打码旁路、参数瘦身——没有一个用到理论的数学核 |

## ② 那 4 条"公理做功"逐条压力测试 → 推翻 3 条

| 声称 | 怀疑者裁定 | 标准工程等价来源 |
|---|---|---|
| **P6′** 截图永远是 Evid、屏内文字不得当指令 | **推翻** | control-data 分离（注入防御 ABC）；CaMeL 已形式化；lethal trifecta 已刻画。P6′ 只是改了中文名 |
| **ε_pool** 会话级隐私预算须独立授予 | **推翻** | 差分隐私 privacy budget + iOS/Android"仅此一次 vs 持续允许"权限模型的换皮 |
| **D23** 放宽必须回根、非单调签发=新授予 | **推翻（最该推翻）** | object-capability 的 attenuation-only 核心定律（ocap / Macaroons / SPKI）的逐字重述 |
| **SILENT** 看似只读、实则改宿主须申报 | **保留，但降格** | 底层是 command-query separation + observability 的换皮；但"识别成一类独立失效"确有 OWASP LLM06 没单独命名的诊断槽位价值——全场最实的一格 |

**共同特征**：做功的构件没有一条是公理核的数学层。测度论 P1-P8、纤维 σ-代数、9 态状态机几何、八相回路——在整个插件设计里一次都没被调用。**把它们从规格里删掉，规格逐字不变。**

## 最锋利的一条：有用度跟具体程度成反比

> 一套真正从第一性原理出发的方法论，应该是**越往具体的泥潭里走、越管用**——硬权衡正是需要原理来裁决的地方。
>
> 这套理论恰好相反：在"评论它"的抽象层它最唬人（公理、定理、机器验证一整套）；每往可动工的方向推一步，外壳就脱一层；到 v2 打磨这个最具体、必须真解决矛盾的阶段，数学核贡献恰好为零。

它残留下来的有用部分（永不静默、最小泄露默认、证据非授权）**全是"姿态"，不是"推导"**——告诉你该用什么态度，不告诉你答案。姿态是检查清单条目；第一性原理方法会**算出**答案。最终画像：**一套穿着"推导引擎"外衣的"姿态清单"。**

## ③ v2 打磨：最强的追加证据

把设计逼到工程完整时，真正驱动每项改进的是什么：

| v2 实质改进 | 真正驱动它的 | 理论角色 |
|---|---|---|
| 7 轴 → 5 正交轴、判别联合让非法组合写不出来 | 标准类型工程 | 无 |
| 坐实"结构提取绕过像素打码"、设计结构脱敏器 | 标准安全思维（攻击面分析） | 给了"Evid"这个名 |
| 模态默认从"最便宜"翻转为"最小泄露面" | 安全默认原则（Saltzer-Schroeder 1975） | 给了"最小泄露面"这个名 |
| ε_pool 扣费点前移到"物化即消费" | TOCTOU / 记账正确性推理 | T-DC.5 提示，修法是工程 |
| 补 PREFLIGHT 失败出口堵"永不静默"的缝 | 状态机完整性检查 | "永不静默"这条**不变量本身**是理论给的 |
| 寻址 DSL、GPU 黑帧回退、CDP 现实回落 | 本机实测逼出的标准工程 | 无 |

> 其中一个真实的硬伤值得专记：**像素级 allowlist 打码保护不了结构提取模态**——CDP 取 DOM / UIAutomation 走控件树能读到隐藏字段、密码框明文、视口外内容，这些正是打码要挡的。这条致命点连带翻转了整套默认策略（"最便宜"→"最小泄露面"），并要求一道**不可关闭的结构脱敏器**。但发现它靠的是标准安全思维，理论只提供了词汇。

## 元发现（也印证了那条担心）

连综合 agent 自己都对理论做了轻度自我美化：它在正文里反复承认这几条的底层都是换皮，却在最终分桶里仍记为"公理做功"——正是"理论**能描述**决策 ≠ 理论**塑造**了决策"的混淆，发生在裁判自己身上，被那个独立的、被要求证伪的怀疑者节点揪出来。这就是"做检验的我和产生理论的是同一类人机回路"这条担忧的活体证据。

## 总裁定

- 作为**诊断检查清单**：在权利关系维度、故障维度**部分通过**——把 sink 提为一等参数、安全重心移到出口、命名几个易漏竞态，是真增量。
- 作为**"从公理推出新设计"的方法论**：**未通过**。最引以为傲的数学/公理层对这个真实插件零做功。
- **净成本**：数学外壳诱使你对"单点只读探针"强套委托链/状态机几何，制造虚假复杂度（3 条"理论误导"全产生于此）。

> 这个插件实验在一个能核对源文、能验证工具语义的真实对象上，独立复现并强化了上一轮判断——**有用的检查表删掉公理照样成立**。要让它从"姿态清单"变成"方法论"，缺的不是再加公理，是反过来：把数学核删掉，把那几条不变量提炼成工程师不读总册也能用的检查表，补上真实文献引用接回生态。
